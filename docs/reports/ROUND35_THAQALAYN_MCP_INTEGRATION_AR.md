## 1. النتيجة التنفيذية

المستودع المطلوب خادم أدوات MCP مكتوب بـ TypeScript، وليس حزمة Flutter أو مكتبة بيانات قابلة للإضافة إلى أصول الهاتف. نقطة النقل فيه `StdioServerTransport`، أي أنه مصمم ليعمل مع مضيف MCP يتواصل عبر stdin/stdout. التطبيق الحالي Flutter ويملك أصلاً تكاملاً مباشراً مع REST API للثقلين؛ لذلك لم أضف عملية Node منفصلة داخل الهاتف ولم أكرر طبقة اتصال لا يحتاجها التطبيق.

تم دمج الوظائف المتوافقة على طبقة التطبيق الحالية، وتوثيق خدمة API والمستودع البرمجي في سجل المصادر، وتوسيع محلل بيانات الروايات لعرض تفاصيل التقييمات المتعددة عندما يوفرها المصدر. لم تُنسخ قاعدة بيانات الثقلين كاملة، ولم تُنشأ روايات أو أحكام من عند التطبيق.

## 2. ماذا يفعل المستودع؟

المستودع يعرّف الأدوات التالية:
- `get-all-books`: جلب فهرس الكتب ومعرّفاتها.
- `get-random-hadith`: جلب رواية عشوائية.
- `search-all-books`: البحث في الروايات.
- `fetch-ingredients`: جلب بيانات المكونات الغذائية وأحكامها حسب وصف الأداة.
- `get-graphql-introspection`: قراءة بنية GraphQL.
- `make-gql-request`: إرسال استعلام GraphQL.

الاعتماديات الأساسية في `package.json`: `@modelcontextprotocol/sdk` و`zod`، والبناء بواسطة TypeScript. الأداة لا تقدم واجهة هاتف، ولا تخزن مجموعة الروايات محلياً.

## 3. نتائج فحص كود المستودع

تمت مراجعة ملفات `src/index.ts` و`src/handlers.ts` و`src/rest/controllers/hadithController.ts` و`src/rest/services/hadithService.ts` و`src/types/types.ts` وملفات الإعداد.

### عيوب مؤكدة في الشيفرة المفحوصة

1. **فحص `bookId` غير صحيح:** يستخدم الـ Controller والـ Service التعبير `typeof bookId !== undefined`. قيمة `typeof` نصية، لذلك يكون الشرط صحيحاً حتى عندما تكون القيمة غير معرّفة. هذا يجعل طلب البحث العام وطلب الرواية العشوائية العامة يذهبان إلى مسار يحتوي `undefined` بدلاً من المسار العام. الفحص الصحيح يكون بمقارنة القيمة نفسها، مثل `bookId !== undefined`.

2. **مسار GraphQL غير متطابق:** `API_BASE` ينتهي بـ `/api/v2`، بينما `graphQLRequest` يضيف `/graphql` إلى هذا العنوان، فينتج `/api/v2/graphql`. ملف API المرجعي يعلن نقطة GraphQL عند `/graphql` على جذر النطاق. أداة introspection تستخدم عنوان الجذر، لكن أداة `make-gql-request` تبني مساراً مختلفاً.

3. **الرجوع البديل في البحث غير ظاهر في التنفيذ:** يذكر README وجود Smart Fallbacks، لكن المسار البرمجي الذي تمت مراجعته في `search-all-books` يستدعي طلب REST للبحث فقط، ولا يظهر فيه منطق محلي مستقل أو رجوع شبكي بديل. لذلك لم أضف وعداً للمستخدم بأن البحث ضبابي أو أن النتائج ستأتي من مصدر بديل تلقائياً.

4. **النقل غير مناسب لتطبيق Flutter مباشرة:** الخادم يفتح اتصال stdio فقط؛ لا توجد نقطة HTTP server في هذا المستودع يمكن للهاتف استدعاؤها كما يستدعي REST API.

5. **معلومات الترخيص متعارضة:** `package.json` يذكر `ISC`، وREADME يقول `MIT`، ولا يظهر ملف `LICENSE` في شجرة الملفات، كما أن بيانات GitHub لا تعرض ترخيصاً محدداً. لهذا لم أنسخ شيفرة المستودع أو أعد توزيعها ضمن التطبيق قبل حسم الترخيص.

6. **لا تظهر مجموعة اختبارات ضمن شجرة الملفات المفحوصة.** لذلك لا أعتبر نجاح فحص ملفات المشروع بديلاً عن اختبارات تشغيلية للمستودع نفسه.

## 4. ما كان موجوداً مسبقاً في التطبيق

كان `ThaqalaynRepository` داخل Flutter يستدعي واجهة REST العامة مباشرة ويدعم:
- فهرس الكتب.
- البحث العام أو داخل كتاب.
- الحديث العشوائي العام أو لكتاب محدد.
- جلب رواية بواسطة معرّف الكتاب ورقم الرواية.
- تخزين مؤقت لفهرس الكتب وآخر مجموعة روايات مستلمة.

لذلك فإن أدوات MCP الثلاث الخاصة بفهرس الكتب والبحث والرواية العشوائية لم تكن وظائف مفقودة من التطبيق؛ كانت مطبقة بالفعل عبر REST، وهو الاتصال الأنسب للعميل المحمول. وتوثيق API الأصلي يحدد واجهات REST وGraphQL للكتب والروايات.

## 5. التغييرات التي أُجريت في هذه الجولة

- توسيع تحليل بيانات الكتاب لقبول الاسمين `BookId` و`bookId`، وقيمة `Volume` أو `volume`.
- توسيع قراءة أسماء حقول تقييم البهبودي/المحسني باختلاف حالة الأحرف والتهجئة الواردة في تعريفات المستودع.
- إضافة قراءة `GradingsFull` عند وصولها؛ تُعرض درجة التقييم واسم صاحب التقييم ومرجعه وتفاصيله المتاحة مع إبقائها منسوبة إلى المصدر.
- استبعاد حقول التقييمات والأسماء والمراجع من اكتشاف نص المتن التلقائي حتى لا يظهر اسم عالم أو درجة تقييم على أنها متن الرواية عند غياب حقل المتن.
- إضافة اختبارات Dart لحالات `BookId` و`Volume` والتقييمات المفصلة المتداخلة.
- تسجيل خدمة الثقلين REST ومشروع MCP في سجل مصادر التطبيق مع توضيح حالة الاستخدام وحدود إعادة التوزيع.
- إضافة تصنيف «تكامل واجهة برمجية» في شاشة المصادر والتوثيق.

**مهم:** تعرض الشاشة تفاصيل التقييم كما وردت من المصدر، ولا يحوّلها التطبيق إلى تصحيح أو تضعيف مستقل. كما أن ظهور نص عبر API لا يعني بذاته أن إعادة استضافته أو توزيعه دون اتصال مرخّص.
